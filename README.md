# 作业发布系统

一个把「给六门课程布置作业」这件事做成三块固定区域的本地小工具：左边是功能区
（调字号、一键布置给全部课程、一键清空、翻历史记录），右上是你一眼看完的课表与
布置情况，右下是可以直接往课表上拖的便捷 Tag。

原生 ES Module，零依赖，没有构建步骤 —— 改完代码刷新浏览器即可。（想发给别人时
可以 `npm run build:exe` 打成一个双击就跑的单文件 exe，见下面「打包成 exe」。）

---

## 怎么打开

双击 `start.cmd`（优先用 Node，没有就退回 Python），浏览器会自动打开
<http://localhost:8777/>。

> **不能直接双击 `index.html`。** 本项目用原生 ES Module，`file://` 协议下
> 浏览器会以 CORS 政策拦截模块加载，页面会一片空白。必须通过 http 打开。

手动启动：

```
node tools/serve.mjs          # 默认 8777 端口
PORT=9000 node tools/serve.mjs
NO_OPEN=1 node tools/serve.mjs   # 不自动开浏览器
```

## 打包成 exe

```
npm run build:exe
```

产出 `dist\作业发布系统.exe`（约 300KB），**双击就能跑** —— 不需要 Node、不需要
Python、不需要 .NET SDK，拷到别的机器上也一样。

它做的事：把 `index.html` 与 `src/**` 作为**内嵌资源**编进一个 C# 小程序
（`tools/exe/Launcher.cs`，用 Windows 自带的 .NET Framework 里那个 `csc.exe` 编译），
运行时在本机 8777 端口起一个极小的静态服务，再用 Edge / Chrome 的「**应用窗口**」
打开它 —— 没有地址栏、没有标签页，看着就是个桌面软件。因为是 `/target:winexe`，
没有控制台窗口，所以挂了一个托盘图标（右键：打开窗口 / 退出）。

- **改完 `src/**` 必须重新构建一次**：exe 里的网页内容是构建那一刻的**快照**。
  开发时照旧 `npm start` 或双击 `start.cmd`，那条路径读的是磁盘，改完刷新即可。
- **端口固定 8777**，和开发服务共用同一个 origin，所以「用 exe 打开是空的、
  用 npm start 打开又有东西」这种事不会发生。**但 exe 用的是专用浏览器配置目录**
  （`%LOCALAPPDATA%\作业发布系统\browser`），而 localStorage 是按配置目录隔离的
  —— 所以 exe 里看到的存档和你日常浏览器里打开 `localhost:8777` 看到的**不是
  同一份**。这么选是为了让存档不被「清理浏览数据」顺手删掉，也不受日常浏览器里
  扩展、插件、代理设置的影响。
- **只绑环回地址**（127.0.0.1 与 ::1），同一台机器之外访问不到。绑两个是因为
  Windows 11 上 `localhost` 常常先解析到 `::1`，只绑 IPv4 会连不上。
- **出问题不静默**：端口被别的程序占住、打不开浏览器，都会弹一个说人话的对话框，
  详细记录追加在 `%LOCALAPPDATA%\作业发布系统\launcher.log`。
- **连点两次图标不会起第二份**：先探一下 8777 上是不是自己人（认响应头
  `X-Homework-Board`），是就只把窗口叫出来。
- **图标只有一份**：`src/assets/icon.ico`。它同时是资源管理器里的文件图标
  （构建时用 `csc` 的 `/win32icon:` 打进 PE 头）、托盘图标（从内嵌资源里读）、
  以及网页的 favicon（`index.html` 里一行 `<link rel="icon">`，Edge 的应用窗口
  和任务栏认的就是它）。换图标 = 换这一个文件再重新构建，没有第二处要改。
  这个小程序里的图标是用户自己给的图，不是编出来的品牌元素。
  这个 .ico 里 16/24 两张不是缩出来的，是照着托盘尺寸另画的（线更少、更粗，
  小了才不糊）。所以托盘那边**必须指名要小图标尺寸**：`new Icon(stream)` 默认
  按 32 挑帧，托盘只有 16，Windows 会把 32 那张缩下来，手绘的两张等于白画 ——
  实测托盘像素与「32 缩到 16」差 4.3、与自己那张 16 差 15.4；改成
  `new Icon(stream, SystemInformation.SmallIconSize)` 之后差 0.23。

## 三块区域

```
┌──────────────┬──────────────────────────┐
│              │          二区            │
│     一区     │   课表 + 作业布置情况     │
│   功能区     │                          │
│ 字号/快捷/历史│            [ 全屏 ]      │
│              ├──────────────────────────┤
│              │          三区            │
│ 软件信息/设置 │      便捷 Tag 区域        │
└──────────────┴──────────────────────────┘
```

- **一区**：功能区。自上而下三块工具——**字号**、**快捷**（布置给全部课程 /
  清空全部作业布置）、**历史**；软件名称、版本、开发者压缩后固定在栏底，
  设置入口也在那里。软件信息默认留空显示为「未设置」——请在设置里自己填，
  本仓库没有替你编造任何真实信息。
- **二区**：核心。2×3 两个表格块，固定为 语/数/外/物/化/生。页脚右下角一个
  「全屏」，让这一块单独占满屏幕。
- **三区**：15 枚默认 Tag —— 必刷题 / U加课堂 / U加课后 / 卷子，加上英语卷面那几样：
  阅读理解 / 七选五 / 完形填空 / 单句填空 / 课文改编填空 / 语法填空 /
  A篇 / B篇 / C篇 / D篇 / 白皮书。都可以填页码、拖动布置；也可以自己加 Tag，
  自建的也一样能填页码。默认 Tag 删不掉（自建的才有 ×），顺序就是上面这个。

布置记录、自定义 Tag、页码、字号、历史都存在浏览器 localStorage
（键 `homework-board:v1`），刷新不丢，不会上传。

## 怎么用

**拖拽**：按住三区的 Tag 拖到课程格上，格子高亮后松手即可。鼠标、触摸屏、
手写笔走的是同一套逻辑。拖到空白处松手＝放弃，不会入账。

**点选**：先点一下 Tag 选中它，再点课程格，效果和拖拽一样。适合不方便拖的场景。

**撤销**：把格内的作业拖回三区，三区亮起接收态，松手就撤销了。这是真删数据，
不是只把画面上的标签收起来。

**改课**：把格内的作业拖到另一门课，颜色当场变成新课程的颜色。目标课里已经有
这一条时，只相当于撤下，不会出现两条。

**页码**：Tag 上 `-页` 那一段是个按钮，点它会在 Tag 上方浮出一个内置数字键盘，
按数字、按「完成」就行。填 20 就显示 `必刷题-20页`，没填时页码那一格是一条虚线；
没页码的条目落到格子里就只有名字，不会多出一截空的 `-页`。
点页码不会误触发拖拽，改完页码 Tag 照样拖得动。

**页码是「每条布置各记各的」，而且用过就清空。** 在三区给「必刷题」填 20 页、
拖进语文，语文那条是 `必刷题-20页`，而**三区那枚 Tag 上的 20 自己没了**——
下一次拖进数学要重新填。所以同一个 Tag 在语上是 20 页、在数上可以是 35 页，
它们互不相干。三区那个数字是**输入缓冲**：填了还没拖走的那次输入，不是 Tag 的
属性。已经在格子里的条目也不会被它影响——拖回三区重放才能改它的页码。

这么定是因为课上真实的动作是「这枚 Tag、这一页」一次一次地放，而不是先想好
一个页数再到处用；顺着上一次的页数会把下一页悄悄写错，而且错了看不出来。

这个键盘是**故意**的，不是没做输入框：软件是给教室触屏用的，一个
`<input inputmode="numeric">` 在平板上点一下就会弹出系统输入法，盖掉大半个屏幕，
而输入法那套候选词、联想、中英切换对一个只可能是 1~999 的整数毫无用处。
所以页码控件是按钮而不是输入框——**页面上一个输入框都没有**（除非你正在给
自定义 Tag 起名），任何设备、任何输入法都弹不出来。键盘是**非模态**的：它开着
的时候可以直接去点另一枚 Tag 的页码，原地改指那一枚，不用先关再开。桌面上
键盘弹出时物理数字键、退格、回车照常可用。Esc、点「完成」、点键盘外面都能收起。

**自定义 Tag**：三区自带 15 枚默认 Tag（必刷题那四样 + 英语卷面那几样），不够
用就点「+ 自定义 Tag」，输入名字回车（最多 12 字）。建好的 Tag
和默认 Tag 走完全一样的逻辑——一样能填页码、一样能拖，鼠标移到它上面会出现 ×，
可以删掉（连同它已布置的记录）。重名不会建出第二个，会指向已有的那个。

**颜色**：三区里的 Tag 一律中性色，落到哪门课才长哪门课的颜色。所以同一条
「卷子」在语上是红的、在数上是蓝的——这是「Tag → 该课程的作业」这个转变本身
的可视化。

**全屏**：点二区右下角的「全屏」，只有作业安排表这一块占满屏幕，2×3 布局
和所有数据原样不动。按钮变成「退出全屏」，按 Esc 也能退出。

**撤下**：鼠标移到格子里的作业标签上，右侧出现 ×，点掉即可。一格塞不下时
是**作业自己缩小**、全都留在格子里，而不是把放不下的那几条藏到滚动条后面
—— 见「字号」那一节末尾。

**重复布置同一个 Tag** 不会被记两次，已有的那枚会闪一下提示「这里已经有了」。

## 一区的三块工具

**字号**：紧凑 / 标准 / 大 / 特大四档，选了就记住，刷新还在。

四档底下走的是**两条阶梯**，因为它们要的东西不一样：

| 档位 | 界面文字 | 课程格里那个大字 | 三区的 Tag | 格内的作业条目 |
|---|---|---|---|---|
| 紧凑 | 13.5px（0.9 ×） | 26.0px | 20.0px | 23.4px |
| 标准 | 15px（1 ×） | 37.8px | 20.0px | 34.0px |
| 大 | 16.8px（1.12 ×） | 54.7px | 20.0px | 49.2px |
| 特大 | 18.75px（1.25 ×） | 79.0px | 20.0px | 71.1px |

（上表是 1440×900 下的实测值。界面文字是 `15px × 系数`；大字不是固定 px，
「格内的作业条目」那一列是从大字乘出来的，而「三区的 Tag」那一列**四档一模一样**，
见下。）

**课程格大字**是课堂上从最后一排要看清的东西，所以它不跟界面文字共用系数，
而是**按科目框的高度算**：特大档正好占框高的一半（说的是看得见的笔画，不是
字身盒，所以字号要略大于一半）。因为它跟的是框而不是屏幕，窗口拉大、进全屏、
窄屏折行，这个字都跟着格子一起变，永远占住同一个比例——全屏下不需要另写一条
规则。紧凑档定在 26.0px，是改版前「特大」档的大小。二区页脚占掉的那 30px 高度
也让这些数一起小了一点（早先是 27.6 / 40.3 / 58.6 / 85.3）。

**格内的条目挂在这个大字上**，乘一个固定比例；**三区的 Tag 不挂了**：

- 三区 Tag = **定值**，四档一模一样（1440×900 下 **20px**、Tag 高 46.6px），
  用户点着数定的：先是「3区 tag 可以再缩小一点」，再是「三区的 tag 20px 就
  差不多了」。`tags.css` 里写成 `2.484cqh`（本列内容盒 805px 的 2.484%）而不是
  一个 `calc(...)`，免得下一个人以为它还跟着档走。
- 格内条目 = **0.9 ×** 大字 **× `--fit`**（「拖进格子之后变大」；大字不封顶，
  所以条目也不封顶，特大档下一条作业几乎占满整个科目格——这是明确要的效果）。
  `--fit` 是「这一格装不下就自己缩小」的系数，平时就是 1，只在挤的格子上
  小于 1，见下面那一节。

Tag 为什么不跟着档走了：挂上去的话「特大」档 Tag 高 151px、十几枚默认 Tag 要把
托盘滚 11.8 屏（实测），而托盘是天天伸手去够的地方；科目大字是「一眼扫过」的信息，
两者不必同进退。代价是**条目的比例逐档不同**（条目 ÷ Tag，也就是落位后的倍数）：

| 档 | 三区 Tag | 格内条目 | 落位后 |
|---|---|---|---|
| 紧凑 | 20px | 23.4px | 1.17× |
| 标准 | 20px | 34.0px | 1.70× |
| 大 | 20px | 49.2px | 2.46× |
| 特大 | 20px | 71.1px | 3.55× |

四档**都是变大**。早先 Tag 定在 27.2px 时紧凑档是反过来的（条目 24.8px 比 Tag
还小，落位演成缩小 0.82 倍）—— 那次是把 Tag 缩到 20px 之后，这个代价自己没了。

倍数虽然逐档不同，却**不用写死**：落点那一层的起步缩放就是「出发字号 ÷ 目标字号」，
上面四个数都是这个式子自己算出来的（格→格是 1、格→三区是 Tag ÷ 条目，四档在
0.28~0.85 之间，同样自动）。

**「从小变大」是个看得见的动画**（用户：「从三区到二区，从小变大的过程要做动画」）：
跟着手指的是三区 Tag 的复制品（拖影）。松手那一刻，拖影里多出一层**克隆自落点条目**
的新样子（`.drag-ghost__arrival`），它一现身就是 Tag 的字号（起步缩放＝出发字号 ÷
条目字号），飞过去的途中长到 1 —— 也就是条目自己的大小。这一层在前两成就实了，
旧的壳（那枚 Tag）慢一步在前三成半里淡掉；两层在交接窗口里**字号相同**，所以文字
大小是连续的，看着只是「壳换了」，不是「跳了一下」。倍数越大给的时间越长（紧凑约
233ms、标准约 262ms、特大约 321ms），因为 3.55 倍和 1.17 倍不是一个观感。

**飞行走的是它自己那条缓动曲线**（`FLIGHT_EASE`，`.3,.05,.2,1`），不是全局那条
`--ease`。因为这一趟是**被松手那一帧推着起跑的**：那一帧主线程要干 20ms 上下的活
（插入条目、重量那一格、克隆落点层、强制回流），浏览器画不出中途帧，拖影会在松手点
原地停十几毫秒。全局那条是快出曲线，停顿之后第一帧就要走完全程的一成半 —— 实测
142px 的位移首帧走 22.4px，看着就是「卡一下」（用户报的又一个毛病）。换成起手轻的
曲线，同一段停顿只压到 3.3px，之后平滑加速（逐帧 0 → 3.9 → 10.1 → 17.7 → 22.6px），
峰值速度与原来相当。**停顿本身消不掉**：那是布置一枚条目必做的活，只能让它看不见。
两层（出发层淡出、落点层长大）跟外层平移共用这条曲线 —— 曲线对不上的话，会先看见
「位置动了、字还没长」这种脱节。

为什么不是把 Tag 那一层直接放大：Tag 与条目不是一个盒子（Tag 有抓手、留白也厚，
同字号下宽 1.8 倍、高 1.35 倍，实测 175×47 对 344×123）。照字号放大之后，空中的
拖影比落点大出一圈，交接时只好再缩回去 —— 用户报的正是这个毛病：「会先变得超级大，
然后再缩小成原来的样子」。换成克隆落点那一层之后，它长到头**就是条目自己的 rect**
（自检逐帧盯着，容差 1.5px），而且全程不比落点大。

真实条目自己**不再放大一遍**（落位期间的 `--enter-scale` 钉成 1）：两段一起长，就分不出是
哪一段在长了。点选布置（点一枚 Tag、再点课程格）没有拖影，那一路才由条目自己从
Tag 的大小长起来，起点同样是现读的「Tag ÷ 条目」。Tag 在三区里不变大（拿起来时
那一下轻微上浮除外）。

**界面文字**四档只在 0.9~1.25 之间，跨度小得多：按钮、标题条都是固定高度的框，
再放上去就撑破了。所以「特大」下界面文字变大、课程格大字变得更大，两件事不是
同一个幅度。

窄屏（≤760px）下这两条都会有封顶，因为 340px 宽的屏幕里放不下课堂投影那一套：

- 界面文字那一条的「特大」封到 1.15——再放大会把课程格压得没有高度可用；
  即便封顶，它仍然比你选「大」要大。
- 科目大字（连同格内条目）封到 **17px**（`--glyph-cap`）。一格只有 165px
  宽，横向排开之后留给作业的只有 100px，而一条带三位页码的作业按 0.9 倍排出来
  光页码就有 3.2em 宽——不封顶的话整条会被格子裁掉，连页码都看不见。
  封的是**大字这一个数**，0.9 那个比例在窄屏照样成立（条目 15.3px）；三区的
  Tag 走同一条上限的 0.75 倍（12.75px），所以窄屏下条目恒是 Tag 的 1.2 倍，
  「拖进去变大」四档一律成立、四个档位量到的都是同一组数。
  代价是窄屏下四个档位在二区、三区看起来一样大：一屏六门课的地方本来就摆不下
  四档字号，而一区的文字、按钮仍然跟着档位走。

**格子装不下的时候，条目自己缩小 —— 不是滚动条。** 一格里的作业摞起来比格子高、
或者某一条宽到把名字和那个悬停才显形的 × 挤出边界时，这一格条目的字号会乘上
一个 `--fit`（0~1），缩到全都看得见为止。几条要点：

- **只缩挤的那一格。** `--fit` 写在那个格子的 `.course-cell__slots` 上，别的格子
  和三区的 Tag 一点没变 —— 自检里拿「一格一条」的格子做对照，量出来还是 0.900。
- **算出来，不是猜的。** 每次渲染完量一遍：竖向按超出的比例一步压到位，横向每次
  退 12%，再用几轮二分长回去，停在**刚好放得下**的那一档 —— 缩小是手段，不是目的。
- **名字要么完整、要么带省略号。** 名字的可用宽度落在「0 到一个字之间」而还在截断
  时，浏览器会画出一个竖着切掉的半个字（看着像错字），所以这种情况也算「挤」，
  宁可整条小一点。页码一位不让。
- **缩到下限还是放不下一个字，就把名字整段收起来，只留页码。** 名字那段连一个
  省略号都排不进去的时候（340px 的窄屏 + 一条 12 字的名字 + 三位页码），留着
  半笔比去掉更难看，而页码才是这条作业唯一的新信息。这是**最后**一招，只在这种
  排不下的格子上出现；名字仍然在 `aria-label`（读屏）和鼠标悬停的提示里，没有丢。
- **下限是 15px**（标准档的界面正文大小），不乘字号系数：字小到看不清是屏幕前的
  人说了算，跟格子多大、选了哪一档无关。缩到下限还放不下（十几条）才退回原来的
  滚动条 —— 那时藏起来也比缩成一片糊诚实。
- **落位动画不受影响**：先缩、再量落点（渲染同步里就是这个顺序），所以飞过去的
  拖影按缩小之后的字号缩放，落地不跳。
- **没变的格子不重量。** 重量一格会弄脏整篇文档的样式，接着的每一次测量都得还这笔债，
  所以就按「这一格的输入有没有变」来决定要不要重算：指纹 = 字号档 + 这一格每条的名字
  与页码（`fitSignature`）。落位那一帧只有真的多了一条的那一格重量，六格从 6 次降到 1 次。
  指纹里**故意不含格子大小** —— 那是窗口变化的事，归 `ResizeObserver` 那一路，它一直是
  无条件下全部重量。

**快捷 · 布置给全部课程**：先在三区点选一枚 Tag，这里会显示选中的是哪一枚，
点一下六门课一起布置；已经有的课跳过，重复点不会叠加。整件事只发一次状态更新，
不会出现「前几门好了、后几门还在等」的半截画面。

**快捷 · 清空全部作业布置**：换一天、换一节课，把上一个班的布置整个抹掉重来。
**只清二区**——三区的 Tag 一枚不少，历史也原样留着（清 Tag 是另一件事，抹掉历史
更是另一件事，都不混进这个按钮）。所以它不是「恢复出厂」：清完还退得回来，
历史里上一条就是清之前那一刻。

破坏性操作就地二次确认：点一下变成红色的「确认清空」，**再点一下才真的清**，
3.5 秒内没动、或点到别处，自己变回原样。二区空着时按钮是禁用的，并且写明
「二区还没有布置。」——不让人对着一个灰按钮猜。这一条和设置抽屉里的
「清空全部作业布置」是**同一个动作**，只是提到了一区手边（实现上共用同一个
`clearAssignments`，按钮的二次确认也是同一个 `confirm-button.js`）。

**历史 · 历史记录**：每次布置、撤下、改课、清空、恢复都记一条，最多留 40 条，
最新的在最上面。每条是**那一刻整块板子的快照**，所以它同时是撤销功能——手滑
撤错了，退回上一条就行，不用自己回忆刚才有什么。写着一行摘要（哪门课有什么），
右侧「恢复到这里」；停在当前那一刻的那条会标成「当前」，不给按钮。

几个刻意的取舍：

- **改页码不单独记账**。页码是每敲一个数字就写一次的东西，记进去会把 40 条
  全冲掉。而且三区那个数字是输入缓冲，还没落到板子上，本来就不是「板子上的
  东西」，撤销、恢复都不该动它（类比 Tag 名输入框里没提交的草稿）。已经放好的
  页码长在布置上，跟着快照一起恢复。
- **首次改动时会先补一条「改动前」**。否则「清空全部」按错之后就再无退路。
- **恢复本身也记一条**，所以恢复可以再恢复回来。
- 上限 40 条自动淘汰，不做手动清空。

## 想改东西时改哪里

**换课程颜色** —— 只改 `src/data/subjects.js` 里对应 `color` 的五个值。
色相类别是硬性约定（语红 数蓝 外黄 物浅蓝 化紫 生绿），只能在同色相内调明暗。
视图不硬编码任何颜色，改这一处全局生效。

**加一个默认 Tag** —— 往 `src/data/tags.js` 的 `DEFAULT_TAGS` 里加一条
`{ id, label, custom: false }`。三区、拖拽、格内渲染都会自动接上，不需要动布局。
（只是加着用的话，直接在界面上点「+ 自定义 Tag」就行，不必改代码。）

**加一个设置项** —— 往 `src/data/settings.js` 加一个字段，类型可以是
`text` / `toggle` / `action`。视图只认识这三种类型，不认识具体字段。

**改课程位置** —— 改 `subjects.js` 里的 `slot`（1 左上、2 左中、3 左下、
4 右上、5 中右、6 右下），两个表格块会自动重排。

**调视觉** —— 颜色、字号、圆角、动画时长都在 `src/styles/base.css` 顶部的
CSS 变量里。

**加一个字号档位** —— 往 `src/data/prefs.js` 的 `FONT_STEPS` 加一条，再在
`src/styles/base.css` 里写一条 `:root.fs-<id> { --fs-scale: 1.1; --glyph-scale: .6; }`。
两个系数都要给：`--fs-scale` 管界面文字，`--glyph-scale` 管课程格大字。两处都要改，
自检里有一组专门盯着这个：档位表在 JS、系数在 CSS，只改一边会红；「大字档位单调
递增」「大字四档跨度 ≥ 3 倍」「--glyph-half 是 cqh 不是 px」也都有单独一条。

**课程格大字的字号** —— 它只有两个数，都在 `base.css` 的 `:root` 里：
`--glyph-half: 17.3cqh` 是「特大档 = 半格高」这个锚点，`--glyph-scale` 是四档系数。
`cqh` 量的是 `.board-block` 内容盒的高（`container-type: size` 在 `board.css`），
一格是它的三分之一。**把 `.board-block` 的三行改成别的行数，17.3 这个数就失效了**
——除了自检会红，没有别的东西拦着。

**格内条目的字号** —— 它是大字的 0.9 倍，跟着 `--glyph-size` 走，别单独写死。

**三区 Tag 的字号** —— **不跟大字走**，是个定值：`tags.css` 里 `.tags-body` 的
`2.484cqh`（用户：「三区的 tag 大小不要随字号变化而变化」，数字是「20px 就差不多
了」换算来的，1440×900 下正好 20px）。`2.484` 是从 `.stack` 的高度换算过来的
—— `.tags-body` 够不着 `.board-block`，所以用不了 `--glyph-size`，而 `.stack`
被声明成它的尺寸容器（`layout.css`，窄屏下退回 `normal`，那时 cqh 会循环引用）。
要改 Tag 大小就改这一个数（想按 px 定：`想要的 px ÷ 805 × 100`）；**改完记得看
四档**：条目 ÷ Tag 的比值就是落位动画要长的倍数，现在是 1.17 / 1.70 / 2.46 / 3.55，
`selftest.mjs` 里那行「字号比例」会把它逐档打出来。

**窄屏的封顶** —— `--glyph-cap` 在 `base.css`，`board.css` 末尾用它压住
`--glyph-size`。三区的 Tag 在窄屏走的是同一条上限的 0.75 倍（`tags.css` 末尾的
媒体查询），不是上面那个 `2.484cqh`：只改其中一处，窄屏下 Tag 会比格内条目还大，
「拖进去变大」就反了。

**改窄屏布局** —— `.tools-*` 自己的窄屏规则写在 `tools.css` 末尾，不写在
`layout.css`。`layout.css` 先加载，同优先级的规则放在那儿会被 `tools.css`
盖掉——媒体查询并不增加优先级。

## 自检

```
node tools/selftest.mjs
```

会启动一个无头 Chrome，用 CDP 派发**真实的鼠标事件**跑完整流程，然后把
24 张截图写到 `.review/`。当前 390 项全通过。

覆盖：三区结构与比例、2×3 布局与六个固定位置、六条课程色条的实际计算颜色、
Tag 存在性、拖拽路径、拖拽中的高亮/拖影/跟手、中途放弃不入账、去重、撤下、
刷新持久化、设置面板的写入路径（软件信息 → 一区、减少动画 → 真实过渡时长、
清空 → 就地二次确认）、窄屏回归、控制台无报错。

Tag 与页码另有一节：默认 Tag 清单（15 枚，逐枚写死、顺序照用户给的）、
页码的录入/只收数字/点页码不误
触发拖拽、三区 Tag 不带课程色、落到六门课各自继承对应颜色（颜色值直接和
`data/subjects.js` 比对）、自定义 Tag 的创建/空名/重名/多个并存/删除/拖拽/颜色、
格内作业拖回三区撤销、格到格改课与合并、二区独立全屏（入口在页脚右下角、
压在课程表下沿、标题条上已经没有它，进出方式、2×3 与数据不变）、以及这些数据
刷新后是否还在。

**页码归位**那一节写的是新模型的不变式，正面反面都有：

- 给一枚 Tag 填 20 页、放进语文 → 语文那条带着 20，**而三区那枚 Tag 上的页码
  是自己空掉的**（`.tag__page.is-empty`）。
- 再填 35、放进数学 → 数学是 35，**语文仍是 20**（各记各的）。
- 改三区那个缓冲数字，已经放好的条目一个字都不变。
- 撤销、恢复历史、清空都不会把页码塞回三区（缓冲不是板子上的东西）；
  但页码跟着快照一起回滚，两个方向都测。
- 旧存档兼容：往 localStorage 写一份改版前形状的包（`assignments` 是字符串数组 +
  `tags.pages`），刷新后板子还在、页码跟着迁移过来，**不需要版本号迁移**。

**字号比例**那一节把上面那张表钉死了：四档逐个真实点击，每档量四件事——
**三区 Tag 的字号四档完全相同**（Tag 固定这条需求最直接的读数）、条目/大字 = 0.9
（容差 0.02）、大字本身逐档变大（对照组，防止「四档都一样」是因为探针坏了）、
以及条目装得进格子且名字没被截掉（字号对得上、渲染成一条空白，是另一种坏法）。
窄屏另有一组：先拿 `--fs-scale` 证明四档真的切过去了（对照 —— 少了它，「四档
一样大」也可能只是四档没切），再量科目大字封顶在 17px、四个档位在二区与三区
看起来一样大、**Tag 一律比格内条目小**（窄屏的倍数恒为 1.2），最后重量一遍
全屏入口还在二区页脚 —— 窄屏那一列的高度由内容决定，桌面量得到不等于窄屏
也量得到。
跑完还会打几行读数，给的是断言说不清的东西：「字号比例 compact: tag 20.0px，
asg/glyph 0.900，拖入放大 1.17× …」四档各一段，倍数一眼可比；「三区：Tag 高
46.6px，15 枚要滚 1.00 屏」记的是 Tag 固定之后托盘的实际体量；窄屏那一组也是
四档一段。落位动画另有一行把每帧的「落点层宽 / 出发层透明度」原样列出来 —— 断言
说的是「有这个性质」，这一行让人一眼看出它的形状：宽度从小长到落点条目的宽度就
停住（不越过它），出发层前几帧就淡掉了。

**拖入放大**那一节在真实拖拽中逐帧录三个盒子（`getBoundingClientRect` 会把元素
自己的 transform 算进去，也就是屏幕上真实的像素大小）：拖影外层、落点层、以及
落点那一枚条目（标尺）。断言：跟手期间屏幕上就是那枚 Tag 本身（落点层还没出现、
尺寸也没变）、落点层的起步缩放＝条目字号 ÷ Tag 字号（容差 0.02，所以交接处两层
字号相同）、长完**就是条目自己的 rect**（容差 1.5px）、**全程不比落点大**（把
「先超大再缩回」这个毛病钉死：改回放大 Tag 那一层，这一条立刻报红，录到的是
落点的 1.8 倍）、且**至少出现 3 个不同的宽度**（是过程，不是一帧跳变）。另有两组
「看得见」的正面断言：**长到九成的那一刻落点层已经实了**（`opacity > .5` —— 淡入
被推到后半程立刻报红）、以及**落位期间 `--enter-scale` 恒为 1**（条目不再二次放大）。
点选布置那条路另有一组对照：起点 ≈ Tag ÷ 条目，标准档下 > 1。

**装不下就缩小**那一节把上面那套行为逐条钉住：往语文里放三条（其中一条带三位
页码）之后，竖向溢出必须是 0（也就是**没有滚动条**）、每一条都整个留在槽位框里
（那个悬停才显形的撤下键也没被挤出去）、名字要么完整要么带省略号（不许是竖着切开
的半个字）、页码 0 裁切、字号守住 15px 下限；同时拿另一格只有一条做对照，量到的
比例仍是 0.900（证明缩的只有挤的那一格）。撤下一条之后还要看剩下的自己重新排大
—— 缩多少是按「当时有几条」算的，不是一次性写死的。压到 340px 再量一遍同样三条：
溢出仍是 0，而且名字要么完整、要么带省略号、要么被整段收起来（`is-nameless`），
三种都行 —— 只有「竖着切开的半个字」不行。

**内置键盘**单独一节。用户提的两件事各有一条正面断言：

- **弹不出系统键盘**：直接断言三区里每一个 `.tag__page` 的 `tagName === 'BUTTON'`
  ——没有输入框就不可能弹键盘；打开键盘后再断言 `document.activeElement`
  不是 input/textarea，全页也没有聚焦的 `input` / `textarea` / `[contenteditable]`。
- **键盘本身**：点数字累加、最多三位、首位 0 被忽略、退格、清空、
  「完成」/Esc/点外面三种关法、物理数字键也能输。
- **摆位**：键盘底边在 Tag 顶边之上、左右上下都没出屏——1440×900 和 340px 各测一遍
  （340px 比键盘本身还窄，这条才真的在测夹取逻辑）。
- **自定义 Tag 的页码**：建一个自定义 Tag → 它有页码按钮 → 设 20 → Tag 上显示
  「数学作业-20页」→ 拖进格内 chip 也是「数学作业-20页」→ 刷新后仍在
  （三区那枚 Tag 上的 20 在拖走的那一刻就清掉了，见「页码归位」一节）。
- **页码不被省略号吃掉**：12 字（名称上限）的自定义 Tag + 999 页放进 340px 窄屏的
  格子里，先断言名字**确实**被截短了（否则下面这条证明不了什么）、而且这一条
  **就在画面里**（量一个滚到画面外的东西，结论再对也没有证据），再断言
  `.asg__page` 的 `scrollWidth <= clientWidth`——页码一位不少地完整可见，
  整页也没有横向滚动。
- 键盘开着时那一枚 Tag 被别处抽走（恢复历史、重置设置都会），键盘自己收掉。

功能区三块工具各有专门断言：

- **纯函数单测**：`formatWhen` 按自然日（不是 24 小时）判定「今天/昨天」、
  跨年补年份，`pushSnapshot` 的 40 条淘汰，`sameAssignments` 的深比较
  （顺序、页码、条数、缺省与 null 等价），`summarize` 的摘要分段，以及字号档位表
  与 `base.css` 的两个系数是否对得上（`--fs-scale` 与 `--glyph-scale` 各查一遍，
  还查大字阶梯单调递增、跨度 ≥ 3 倍、`--glyph-half` 是 cqh 不是 px）。
  这些逻辑界面上「看着对」说明不了什么，所以直接 import 进来跑，并注入固定的
  「现在」——否则期望值会跟着跑测试的钟点变。
- **字号**：四个档位逐个真实点击，断言的是**计算出来的字号**，不是根节点的类名
  ——类名挂对了但 CSS 没跟上是最容易出的错。正文断言 `= 15px × --fs-scale`；
  课程格大字断言 `= --glyph-half × --glyph-scale × 块内容盒高`——它的尺寸由格子高
  推出来，所以期望值也要跟着量回来的格子高算，不能写成某个固定 px。
  两条用户直接提过的锚点各有一条专门的断言：**特大档下那个字的墨迹占科目框高的
  50%±1.2%**（用 canvas 按当前字号量真实的笔画高度，不是量字身盒），
  **紧凑档等于改版前「特大」档的比例**（27.5px / 166.8px 格高）。
  另外每个档位都量一遍固定高度的容器有没有被字撑破（`scrollHeight <= clientHeight + 1`），
  特大档下设置抽屉里的输入框也在量。再有一条专盯「大字把作业区挤没了」：
  特大档下每个格子里大字的行盒不许顶出格子，且剩下的作业区至少还放得下一行标签。
  还有：刷新后仍是特大、窄屏封顶后仍比「大」大、回到宽屏自动恢复原值。
- **一键布置**：没选 Tag 时禁用并说清去哪儿选、点选后按钮可用、六门课各 +1、
  重复点不叠加、只产生一条历史、上次布置时间立刻出现在一区。
- **一键清空**：按钮在「快捷」块里、二区有东西时可用、说明里写着要清几项以及
  三区与历史都保留；第一次点只变文案（红色的「确认清空」）且**一项都没清**，
  第二次点才真的清；清完三区的 Tag 一枚不少、按钮自己禁用、说明换成
  「二区还没有布置。」；整件事只记一条历史（摘要写着空板）、上一条变成可恢复。
- **历史**：条目顺序与「当前」标记、摘要按课程分段、恢复到某一刻板子真的回去
  （含页码，两个方向都测）、恢复本身可再撤销、撤销不会把页码塞回三区、
  Esc 关抽屉后底层解除 inert。

一区改版后，「软件名 / 版本 / 开发者仍在、未设置仍在、设置入口仍能打开抽屉」
这几条是独立断言的——它们是「一区还是原来那个一区」的验尸点。

**软件名**默认是「作业发布系统」，写在 `src/core/persist.js` 的 `APP_NAME`
一处，一区栏底与浏览器标签都取它。这里有个只在改名时才会遇到的事：默认值只
影响第一次打开，用过的存档里早就把**当年那个默认名**写进去了，光改默认值等于
没改。所以 `loadState` 会认一下这个名字（`LEGACY_APP_NAMES`，见
`sanitizeAppName`）：是旧默认名就换成新名，用户自己填过的一个字不动。
自检里「软件名仍在」「复位后名称回到默认」两条钉的就是它。

自检跑完会把 localStorage 清干净再刷新一次，所以你下次打开看到的是初始状态。

需要先起服务（`node tools/serve.mjs`，或者双击 `dist\作业发布系统.exe`）。可用
`APP_URL`、`CDP_PORT` 覆盖地址与调试端口 —— 先跑起 exe 再
`APP_URL=http://localhost:8777/ node tools/selftest.mjs`，整套流程就连同截图一起
打在 **exe 自己的服务**上了，这是「打包没打坏」最硬的证据。

## 已知取舍

- **软件改过一次名，两处老名字要认。** 作业布置软件 → 作业发布系统。存档键
  （`homework-board:v1`）**没跟着改**：localStorage 按 origin 隔离，键一改，
  用户布置好的板子与自定义 Tag 就全看不见了。存档里那份「老默认名」由
  `sanitizeAppName` 换成新名（见上面「自检」一节）；`%LOCALAPPDATA%` 下的
  服务目录改名时整个搬过去，搬不动（老窗口还占着）就继续用老目录 —— 宁可名字
  不统一，不能让人打开看见空板子。
- **窄屏**（≤760px）三区改为自上而下排列。六门课程仍保持 2×3 两个表格块，
  颜色、Tag、拖拽目标都不减。已测到 340px：六种课程色仍可区分、色条仍贴在
  格子上、课程格首屏完整可见、拖拽照常可用（三区要滚一下才够得着，真人也是
  这么做的）。窄屏下三块工具并排折行，所以一区比竖排时矮一半——一区一高，
  课表就被顶出屏幕。
- **窄屏下科目大字、Tag、条目一起封顶**（大字 17px；Tag 取它的 0.75 倍 12.75px，
  条目 0.9 倍 15.3px）。不是省事，是 340px 的一格放不下「0.9 × 半格高」的条目：
  不封顶时一条带三位页码的作业连页码都会被格子裁掉，而页码是最不该被裁的那一段。
  封顶之后条目恒是 Tag 的 1.2 倍，「拖进去变大」四档一律成立（自检里四档各量一遍，
  四档量到的都是同一组数），代价是四个字号档在窄屏的二区、三区看起来完全一样大
  ——一屏六门课的地方本来就摆不下四档字号。这条只在窄屏生效，桌面和全屏不受影响。
- **「Tag 不随字号变化」的代价如今只剩两条。** Tag 定在 27.2px 时紧凑档的条目
  （24.8px）比 Tag 还小，「拖进去变大」在那一档反成了缩小；缩到 20px 之后，
  四档的条目都比 Tag 大（1.17 / 1.70 / 2.46 / 3.55 倍），这一条自己消失了。
  仍然成立的两条是下面「特大档看着小很多」和「一屏装得下」。
- **落位比从前慢一点。** 150ms → 紧凑约 233ms、标准约 262ms、特大约 321ms（倍数越大
  给的时间越长）。这是「让变大看得见」的必要代价；嫌拖沓就调 `panel-board.js` 里
  `LANDING_MS` 这一个常数。
- **起手比从前慢半拍。** 换了缓动曲线之后，头 50ms 走的距离比原来少（原来是一上来就冲，
  那正是「卡一下」的来源）。这条曲线是可以调的：`cubic-bezier` 的第一个控制点越大、
  起手越快，`.3` 是「停顿看不见」与「起步不迟」之间实测出来的折中。
- **松手那一帧仍然是 20ms 上下的活**（插条目、量那一格、建落点层、强制回流）。这一帧画
  不出来是事实，能做的只是让这一帧里的拖影**不要动**（起手轻的曲线就是干这个的）。
  真要更快，得把布置这件事拆成两帧做，代价是落点层的尺寸会慢一帧才准。
- **落位途中会「换壳」。** 飞过去的是 Tag（带抓手、白底、厚留白），落下来的是格内
  条目（课程色、没有抓手），两个盒子本来就不一样大（同字号下 Tag 宽 1.8 倍）。所以
  松手之后的前三成里，旧壳淡出的同时新壳淡入 —— 变的是外观，字号始终连续。若想
  全程只有一个壳，就得让跟着手指的那个东西一拿起来就是条目的样子（那会牺牲
  「拿起来的就是三区那枚 Tag」）。
- **特大档下三区看着比二区小很多**：Tag 20px 对科目大字 79px，两块区域不再成
  比例。科目大字是「投影上要看清」的，Tag 是「手边要够得着」的，两个目标不冲突
  就各自取最优了。
- **三区 Tag 现在一屏装得下**：15 枚默认 Tag 在 1440×900 下不用滚，自检量到的
  「滚几屏」是 1.00（内容正好等于一屏，没有溢出）。作为对照，早先 Tag 跟着档走
  的时候，「特大」档要把托盘滚 11.8 屏（那次实测）。代价是 Tag 比二区的字小得多
  （见上一条），而托盘是伸手去够的地方，小一点换来的是「不用先滚再点」。
- **挤的格子里，条目的字号小于「0.9 × 大字」。** 这是「装不下就缩小、而不是滚动」
  的直接代价：三条特大档的作业挤在一格里，条目会缩到 0.3 倍上下，科目大字不变。
  想回到「一律 0.9、装不下就滚动」，把 board.css 里 `.asg` 字号那个
  `* var(--fit, 1)` 去掉、再删掉 panel-board.js 的 `fitCell` 即可 —— 那是这次
  改动的反面，要单独定。
- **窗口不宽不窄的那一段（桌面布局刚生效时），条目本来会顶到横向边界** ——
  实测 4 档 × 9 种宽度共 36 组里页码从未被裁，被吃掉的是名字、再是那个悬停才显形
  的 ×（1440 下溢出 25px）。现在这三样都由「缩到放得下」保住了：自检里三条作业
  （含一条三位页码）挤在一格，量到的竖向溢出是 0、每一条都整个在框内、页码 0 裁切、
  名字要么完整要么带省略号。代价回到上一条：那一段宽度下条目比 0.9 倍小。
- **窄屏上名字可能整段消失。** 340px 的一格里放一条 12 字的名字 + 三位页码，
  名字那段连一个省略号都排不进去，这时条目只剩「-999页」——名字仍然读得出来
  （在 `aria-label` 和悬停的提示里），但屏幕上没有。比它更小的窗口本来就不该
  开这个软件：340px 已经比任何在售手机都窄。
- **已经放好的条目改不了页码**。页码跟着布置走之后，三区那个输入缓冲和已落地的
  条目就断了联系，要改只能拖回三区重放。这是「用过就重置」的直接代价。
- **一区那个「清空全部作业布置」和设置里那条是同一个动作**，不是两套实现，
  设置里那条也还在。
- 课程格里的作业标签按行换行排布；装不下就**缩小**（见上面那一节），只有缩到
  15px 下限还放不下时才在格子内纵向滚动。也就是说滚动条是最后手段，
  不再是一装不下就出现的东西。
- 格子里的作业标签是**两段**：名字（可省略）和 `-20页`（不可省）。放不下时被
  省略号吃掉的是名字——「必刷题」人人都知道，「第几页」才是这条作业唯一的新
  信息，不该是它被切掉。代价是这条标签内部多了一个节点、一次文案同步。
- **页码不能直接打字了。** 这是「任何设备都不可能弹系统键盘」的代价：页码控件
  是按钮，输入只走内置键盘。桌面端在键盘弹出时按物理数字键即可，速度不降；
  触屏上本来就该是按键。键盘上不给「上一页/下一页」这类语义键，也不收负数、
  小数——`MAX_PAGE` 就是 999 的正整数。
- 全屏用的是浏览器原生的 Fullscreen API，所以它必须由一次真实点击触发
  （脚本直接调会被浏览器拒绝）。被拒绝时按钮保持原状，不会假装进了全屏。
- 数据只存在本机浏览器。清缓存会丢，换浏览器看不到——这是刻意的，
  工具本身不联网。
- 历史记录里指向某个自定义 Tag 的条目，在你删掉那个 Tag 之后会在下次载入时
  被清掉（引用的 id 已经失效）。这是刻意的不追溯，界面不做额外解释。
- 没做键盘快捷键：数字键 1-6 会和自定义 Tag 的名字输入框直接冲突。页码那一路
  已经不冲突了（页码没有输入框了），但 Tag 名那一头还在，所以这条依然成立。
  反过来，**页码键盘开着时物理数字键归键盘接管**——这不违反上面这条：键盘只在
  编辑页码时存在，而且它自带一道保险，焦点在 input/textarea 上时一律不抢。
- **exe 里的网页内容是冻结的**：改了 `src/**` 不重新 `npm run build:exe`，
  双击出来的还是老版本。开发和预览请走 `npm start`。
- **exe 与日常浏览器是两份存档**（专用配置目录 → localStorage 按配置目录隔离）。
  好处是存档不会被「清理浏览数据」误删，代价是想在两边看到同一块板子做不到。
- **exe 用系统自带的 C# 编译器构建**（`csc.exe`，`.NET Framework 4.0` 那一份）。
  极精简的 Windows 上它可能被移除；不在默认位置时用环境变量指定：
  `set CSC=<csc.exe 的完整路径>` 再 `npm run build:exe`。
- **exe 只监听环回地址**：同一台机器之外访问不到（要用局域网投屏设备的话得另说，
  那也意味着别人能打开同一份存档）。
- **exe 与托盘都没有自定义图标**，用的是系统默认图标——本项目不擅自编造品牌元素。
